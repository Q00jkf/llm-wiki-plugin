# vault 的 collab.md 格式

> `.claude/office/collab.md`（1.16.0 前是 `wiki/meta/coordination.md`）的 vault 擴充與維護原則。
> 共通骨架與「只有主管寫」在 pixel-office skill `team` 的 `lead.md` §2；這份只寫 **vault 多出來的**。上層：`SKILL.md`

🔴 **本頁是「索引＋當前狀態」，不是紀錄本**：每列一行，細節不展開；要處理某件事時，才照該列的指向去讀真相來源或 log 對應段。
> 為什麼：每位接任主管都要整份讀這頁。實例（2026-10-05）：某 vault 的本頁長到 24 KB（待辦約 1 萬字、主管裁定約 8 千字），
> 精簡成每列一行、原文逐字搬進 `wiki/log.md` 後剩 6.6 KB，資訊一筆沒丟。

## 結構＝`team` 骨架＋vault 擴充

| 段 | 來自 | vault 多了什麼 |
|---|---|---|
| frontmatter `maintenance: transactional`、`updated:` | vault | `tidy_check` 靠它掃這檔 |
| `# 主管` | team | 多一欄 **peer**：`\| 主管 \| 範圍 \| 上層 \| peer \| 上線 \|`（`role_cards.py` 依表頭找 peer 欄） |
| `# 在線` | team | 角色欄寫角色名（`role_cards.py list` 靠它對持有者） |
| `# 檔案佔用` | team | `occupancy_check.py` 機械比對（見下「注意事項」） |
| `# 待使用者裁示`、`# 等外部回覆` | team | 狀態欄開頭寫登記日（T9） |
| `# 等使用者本人動手`、`# 未指派／未處理` | vault | 同上 |
| `# 凍結中` | vault | `\| # \| 事項 \| 解凍條件 \|` |
| `# 主管裁定` | vault | `**#N（日期）｜結論一句** — 細節：log YYYY-MM-DD <條目標題>` |
| `# 衝突紀錄` | team | — |

舊 vault 的標題（`# 主管名單`、`# 目前主管` 一行字、`# Session 狀態`、`# 待裁示／待辦` 底下的 `##` 分組）腳本照讀；`role_cards.py migrate` 搬檔時只改前三個標題，其餘原樣。

## 🔴 發現的問題一律登記在這裡，而且要有「等誰」

session 工作中發現的任何問題、疑問、待確認，**統一登記在本檔**，不要只留在自己的角色卡、`log.md` 或產出物裡
—— 角色卡只有持有者自己看，log 是歷史不是待辦，產出物上的免責句會被人編版面時順手刪掉。
三份紀錄、零個收件人，問題就整個沉掉，直到有人自己想起來。

進哪一區看**誰能結案**，不是看問題大小：

| 誰能結案 | 區 | 必填 |
|---|---|---|
| 只有使用者能決定（取捨、對外說法、優先序） | 待使用者裁示 | 真相來源 |
| 要使用者親自操作（權限、外部系統） | 等使用者本人動手 | — |
| 公司內某人給事實（同事、擁有者、外部團隊） | **等外部回覆** | **等誰**（知道是誰就寫名字；使用者沒說就寫「未指明」，不要猜一個名字填上去） |
| 沒人在等、無期限 | 未指派／未處理 | 真相來源 |

- 🔴 **待確認事項 MUST 有收件人欄位 —— 沒有「等誰」的不是待確認，是自己的 TODO。**
  重點是「有人在等」，不是「有名字」：不知道是誰就寫「未指明」，使用者看到自然會補。
- 有期限的另外 `python "${CLAUDE_PLUGIN_ROOT}/scripts/agenda.py" add` 一行，`→` 指回本頁編號
  —— 本頁沒有時間軸，不會自己跳出來。
- **狀態欄開頭寫登記日** `2026-10-08｜🟡 …`：守門腳本 `tidy_check.py` 的 T9 靠它，
  登記超過一天還沒結案就在每次開場提醒一次，免得放著沉掉。沒寫登記日的只會被報個數、不會被點名。
  （不另外加一欄：加欄會讓待辦列變 5 欄，被 T1 的「進度勾選表」排除條件吃掉。）
- **產出物上的那句免責另算**：它是「給讀者的」，不是「給自己的待辦」，兩者都要寫，不是二擇一。
  免責句被改掉 ≠ 問題解決。

## 各區寫法

| 區 | 寫 | 不寫 |
|---|---|---|
| 主管 | 每位主管一列：名稱、範圍、上層、peer、上線時間 | 前任的歷程、離線的主管 |
| 在線 | 一列一個在線 peer；跨界接手時該列附三行交接包 | 離線者（收尾即刪） |
| 檔案佔用 | **真實佔用**：現在誰握著哪個檔 | 待辦、裁示（曾混進 21 條，是結構性錯位） |
| 待裁示／待辦 | **每列一行**：事項一句＋指向（真相來源路徑或 log 段落） | 展開細節、子項清單、討論經過 |
| 主管裁定 | **結論一句**＋指向 log；只留結案後仍有「防止重做」價值的 | 起因、論證、已刪待辦的墓碑 |
| 衝突紀錄 | 誰、什麼、**以誰為準、對方怎麼收尾** | 兩邊說法各記一遍 |

## 一列長到需要展開時

1. 把該列原文**逐字**搬進 `wiki/log.md` 當天那一條，用 `<details><summary>#N 原文</summary> … </details>` 包起來（log 整份讀不到，摺起來不影響 Grep）。
2. 本頁那一列縮成一行，細節欄寫 `log YYYY-MM-DD <條目標題>`。
3. 編號不動。搬之前先確認 log 裡真的寫進去了，再刪本頁的長文。

🟡 **軟上限：本頁超過約 8 KB** → 收尾時照上面三步精簡（`wiki-day` 的 `end-manager.md` B 有這一步）。不是硬擋，只是警戒線。

## 注意事項

- **快照檔，覆蓋式更新，不是 log** —— 歷程照舊寫 `wiki/log.md`。
- 🔴 待辦要分組，不要一張長表 —— 使用者最需要一眼看到「卡我本人的有哪幾條」。
- 佔用表的**檔案欄用反引號寫可對到磁碟的路徑片段**、**佔用者欄寫 session 名稱**、**起始欄含 `YYYY-MM-DD`** —— `occupancy_check.py` 靠這三欄機械比對。
  凍結寫「🔒 凍結」；使用者持有寫「使用者」。不寫猜測。
- 名稱從 `ListAgents` 消失**不得逕自判定棄坑**（可能只是重開改名）—— 重跑 `ListAgents` 並向新 session 確認身分。
- 主管沒有真正的檔案鎖；但衝突發生後，主管的裁定是結論不是建議。
- 主管 session 結束不會自動卸任；離線主管那列由下一位上線的主管刪，不必做卸任流程。
- **範圍空白**：只有一位主管時＝全 vault（舊用法行為不變）；與別的主管並存時＝**其餘**（沒被別人範圍涵蓋的）。
  主管上線時兩種情況要先問使用者：兩位的明確範圍重疊，或兩位都空白。
- **誰是我的主管**（peer 報到、收工、角色卡登記都照這一份；`role_cards.py current_manager` 是同一套）：
  peer 欄有你的那位 → 只有一位就是他 → 唯一範圍空白的那位。
  主管欄有讀不出名稱的列時只看第一項（少算一位，後兩項會判錯人）。**判斷不出就報名單第一列**，訊息寫「不確定歸屬，請轉」。
- **多主管分工**（檔案沒有鎖，後存檔無聲覆蓋先存檔）：每位主管只改**自己那列**、**自己 peer 的**「在線」列、**自己範圍的**佔用與衝突；
  `hot.md` 今日結論每位主管各寫一塊、開頭標自己名稱，不改別人那塊。別人的列過期了 → 通知那位主管或使用者，不代刪（已離線的主管列例外，見上）。
- 舊 vault 的「# 目前主管」（一行字）照樣讀得懂；本檔不在樣板裡，格式改了推不過去，主管上線時順手改成表格。
- 檔案歸哪位主管看範圍欄；**跨兩位主管範圍的佔用與衝突交使用者裁示**（本 skill `collab.md` 來訊表）。
- 純被動：不用 `/loop` 自我喚醒。沒有新訊息時什麼都不做。

# 收尾：主管段

> 驗證 → 清理 → 落盤 → push → 交接
> 上層：`wiki-end/SKILL.md`（協作模式且本 session 是主管時才走這份；2026-10-04 自 wiki-collab/05-收尾.md 搬入）
🔴 **順序不可顛倒：先驗證，再落盤，最後 push。** 驗證失敗就不落盤，免得把壞狀態記成事實。

## A. 驗證（全部要綠才往下）

| 檢查 | 指令 | 常見狀況 |
|---|---|---|
| 佔用有沒有被遵守 | `python "${CLAUDE_PLUGIN_ROOT}/scripts/occupancy_check.py" --quiet` | 見下方 |
| 工作區乾淨 | `git update-index --really-refresh` ＋ `git diff --name-only HEAD` | ⚠️ 不要只用 `git status`（stat cache 會誤報乾淨） |
| 孤兒鎖檔 | `find raw -name '~$*'` ＋ `tasklist \| grep -iE "winword\|excel\|powerpnt"` | Office 沒在跑卻有 `~$`＝當機殘留，會讓「檔案是否開啟」判斷失準 |
| vault 健檢 | `/wiki-doctor`（動過 wiki 才跑） | 老化訊號先處理再收 |
| vault 自訂檢查 | `wiki/ops/end.md`、`wiki/ops/collab.md` 列的腳本 | |

## B. 清理：每日收尾必刪一次

> 為什麼：只加不刪的快照檔會膨脹到沒人讀，沒人讀的進度頁等於沒有進度頁。

**逐一打開當天用過的快照檔，刪三類內容：**

| 檔 | 刪什麼 |
|---|---|
| `wiki/meta/coordination.md` | ① 退休／離線的 session 列（含卸任前主管）② 已釋放的佔用列 ③ 已裁示／不做／已消解的待辦列 ④ **展開成多行的列**：原文搬進當天 log（`<details>` 包）、本頁縮成一行指向 log（見 `wiki-collab` 06）；本頁超過約 8 KB 時逐列檢查 |
| 當天用過的 `_README.md` | ① 已完成的缺口列與工作順序列 ② 已被裁示不做的列 ③ 與現況矛盾的過期敘述 |
| `wiki/hot.md` | 依檔頭輪替規則修剪（≤150 行；標「里程碑保留」者不刪） |

🔴 **刪之前唯一一道關卡：`grep` 確認 `wiki/log.md` 有沒有記載。** 查不到 → 先補寫進 log 再刪。
> 實例：8 條已結案裁示中 6 條在 log 零命中，直接刪就整個消失。
> 🔑 最不能丟的一類＝**界定「什麼不是我方範圍」的裁示** —— 那正是防止未來 session 把同一缺口重新打開的東西，它沒有別的家。

**刪除紀律**
- 直接刪整列，不留「✅ 已完成」「已併入 №X」墓碑（見 03 §4）。
- **編號沿用不重編** —— `_README.md`／`coordination.md`／`log.md` 以號碼交叉引用，重編會斷。空號是正常的。
- 刪完檢查引用完整性：正文若還引用剛刪的號碼 → 那是缺口在流失，補回來。
- 腳本抓不到的一類：整列講的事已在別處結案但沒有 ✅ 標記 —— 只能靠真的重讀一遍。

## C. 落盤（三處，職責不重疊）

| 檔 | 寫什麼 | 不寫什麼 |
|---|---|---|
| `wiki/meta/coordination.md` | 當前狀態快照 | 工作歷程 |
| `wiki/log.md` | **當日歷程**：發現路徑、誰踩到什麼坑、裁示理由 | 規則本身 |
| `wiki/hot.md` | **主管寫一塊今日結論**（格式見 `SKILL.md`），peer 不寫 | 完整清單 |
| 各 `_README.md` | 由主管維護（見 01） | |
| `wiki/meta/roles/*.md` | **不改**：各卡進行中事項由持有者收工時寫；主管只讀來彙整（`role_cards.py list` 看進行中行數，持有者已離線而卡沒更新的，在 hot.md 標出來） | 別人的卡 |

⚠️ **`wiki/log.md` 最常被漏** —— peer 各自寫了片段，主管的裁示與跨案脈絡沒人記。收尾時補。

## D. push

```
git status -sb          # 看 ahead 幾個
git push
```
⚠️ 不要等使用者叫才 push —— 累積十幾個 commit 沒推，等於一天的工作只存在這台機器上。

## E. 交接點（收尾報告＝明天的起點）

四段，各一句到一行：
1. **今天做完什麼**（進度 X→Y、幾個 commit）
2. **卡在誰身上**（逐項標明對象，不是籠統「等外部」）
3. **卡使用者本人的**（單獨列，那是他明天第一件事）
4. **peer 狀態**（誰待命、誰手上還有檔）

## occupancy_check

比對 `coordination.md` 佔用表 vs 各檔的 git author：**起始日期之後有非佔用者動過 → WARN**。
三類：`O1` 佔用違規（凍結列另標）｜`O2` 檔案欄解析失敗｜`O3` 佔用者不明。exit 一律 0，是提醒不是閘門。

- 🔑 **只在收尾跑，不要開場跑** —— 它查的是「這段期間有沒有人越界」，開場沒有新資訊。
- 自動備份的 author（如 obsidian-git 用的帳號）在 `raw/.manifest.json` 的 `config.occupancy_ignore_authors` 排除，否則第一天就洗版。
- 「使用者」持有的列不比對（使用者動檔永遠合法），但仍列出標「未檢查」，不靜默通過。
- 🔴 **佔用表不得寫猜測**：寫「原 -aa（疑為 -bb）」會讓兩個名稱都成合法持有者，該列本該紅卻判綠。
  不確定就寫「待確認」並**不要授權動檔**。

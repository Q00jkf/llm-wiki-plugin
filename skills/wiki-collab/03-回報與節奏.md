# 回報與節奏

> 階段回報、BLOCKED、紀錄精簡、裁示不產生待辦、流程強度、回報格式
> 上層：`SKILL.md`

## 1. 階段回報閘門（MUST）

> 為什麼：主管連續處理多輪 peer 來訊才回報一次，使用者說「你可以先跟我報告嗎，不然我抓不到進度」。
> 問題不是回報寫得不好，是**時機太晚**。

**主管自己**
- **每完成一個階段就回報**。一個階段＝一件可交付的事（登記完一個 peer／下完一個裁定／改完一份檔），不是「處理完所有來訊」。
- 回報二選一（可並行）：① 一句話講現況＋下一步 ② 主動開檔讓使用者檢查。
- **收到 peer 來訊時，先回報使用者再回覆 peer。**
- ⛔ 不可為了「一次講完比較完整」連跑三四輪工具再回報。

**對 peer**
- 派工／核准佔用時一併寫明「每完成一個階段回報一次，不要整批做完才回」。
- peer 回報階段完成 → 主管**同一回合**轉達使用者。

---

## 2. 🔴 待放行清單（BLOCKED）

> 為什麼：權限分類器擋下 peer 時，使用者不知道哪個視窗在等放行。分類器是 Claude Code 機制，**主管轉達的放行無效**，只能使用者在該視窗輸入。

- **peer**：一被擋 MUST 立刻傳主管 `🔴 BLOCKED [名稱]：<被擋的動作>`，然後停下。
- **主管**：每則回覆**第一行**固定寫 `🔴 待放行：-xx（動作）、-yy（…）`；無則省略。peer 回報已放行／完成才移除。
- ⛔ 不可把放行混在長回覆中段；⛔ 不可自行轉達放行給 peer。

---

## 3. 開檔（讓使用者檢查產出）

規則在 `wiki-core` R4（回覆末行列「已寫入」路徑、`.md` 走 Obsidian `open … newtab`、Office 走 `start`）。
主管與 peer 都適用；peer 回報給主管時也附路徑，主管彙整後再開給使用者。⚠️ 開 Office 檔會改 byte，見 `07-技術提醒.md`。

## 4. 紀錄精簡原則（MUST）

**移除的內容直接刪，不留痕跡式註記。** 歷程歸 `wiki/log.md` 與 commit message；快照檔只寫**當前狀態**。

| ❌ 不要寫 | ✅ 直接 |
|---|---|
| `№10 已併入 №9` | 刪掉 №10 那列 |
| `~~舊值~~ → 新值`、`（原為 A，某日改為 B）` | 只留新值 |
| 已完成事項留在待辦表標 ✅ | 刪掉該列 |

例外（唯一）：正式受控紀錄本身依其版本並存慣例不刪。

## 5. 🔴🔴 裁示不產生待辦（最高優先）

> 使用者原話：「我之前明明提過定案，你今天卻還跟我說要做這兩件事。之後我不想再看到討論這兩個問題。」

失效機制（有 commit 為證）：
```
使用者裁示 → 主管記「✅ 已裁示」→ 同一筆 commit 又衍生新待辦
             「雖然定案了，但還有 X 風險／依據要備妥／紀錄沒人留」 ← 這條活下來，日後被當未辦事項重報
```
🔑 本質：**把「決定」翻譯成「風險」，而風險會長腳。**

**MUST**
1. 裁示落下 → 該項**即刪除**（不是改成 ✅ 留著）
2. 裁示不得衍生任何新登記 —— 缺口、風險、待備妥、待確認都不行
3. 認為有殘餘風險 → **當輪當面講一句，由使用者決定**。他沒說要處理，就是不處理
4. 裁示內容寫進 `wiki/log.md`（含「不得再提」字樣）—— 那是防止未來重新發現後又跑一輪

**結案時清三個登記面**（漏一個，下個 session 開場就會讀到並重提）：
`wiki/hot.md`（🔴 最容易漏，它是開場必讀）／`wiki/meta/coordination.md`／相關 `_README.md`

## 6. 🔴 流程強度配合動作的可逆性

> 使用者原話：「你為什麼不是把舊的丟到廢止、新的複製過去就好？我們剛剛花了很多 tokens 在這上面。」
> 根因：把「正式紀錄要謹慎」的標準套用到所有動作上。

| 動作 | 流程 |
|---|---|
| 動正式紀錄／刪檔／改判準／改版次 | 回報方案 → 裁示 → 全套驗收 |
| **搬檔、備份、新增非受控資料夾、複製副本** | **直接做，做完回報一句** |

低風險動作的上限：工具呼叫 **2 個**（找檔；複製＋比 hash＋commit）、不跑驗收腳本、commit 一行、回報一句。
**判準：這個動作會不會改變任何檔案的內容？** 不會 → 上述一項都不要多做。
🔴 界線：「新建文件要問」防的是主管自行擴張，**不是**使用者已交辦的事的執行細節（放哪個資料夾）還要再問。

## 7. 回報格式

```
做了什麼：1 行
驗證：1 行（「讀回驗證全過」即可；異常才展開）
需裁示：有才寫
```
- ⛔ 不交完整驗證表 —— 只有異常值得占篇幅。
- 派工與回覆**只寫新資訊**，不重述對方已知背景（例外：更正、跨 session 轉達）。
- 複驗只做「會導向動作」的：peer 說「缺 X」而你要據此派工 → 驗；純狀態數字 → 不必。

## 8. 🔴 對使用者的事實陳述也要能答「我怎麼知道的」

> 曾六次用推論代替查證，全部由 peer 擋下；最危險的是**轉述 peer 的結論**：主管把 peer 未驗證的「原廠沒印過這個版本」
> 當事實轉給使用者，使用者據此裁示改 22 份檔名，peer 自己逐份查證後才推翻。

講數字、版本、日期、份數、因果時，心裡要能立刻答出「**開過哪個檔／哪一行／哪個指令的輸出**」。
答不出來 → 標「（推測，未查證）」或先去查。**轉述 ≠ 查證。**

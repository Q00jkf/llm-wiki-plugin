# 讀書知識庫 — 建立 SOP（訪談式）

> **這份文件是什麼：** 一份「設計精靈」。當你準備好要建讀書知識庫時，照著下面的問題逐題回答（或直接對 Claude 說「跑一次 SETUP-SOP」，讓 Claude 一題一題問你）。回答完，第 5 節會把你的答案翻譯成實際的資料夾結構與筆記模板。
>
> **為什麼用問問題的方式：** 讀書知識庫沒有標準答案。同樣是讀書，有人要的是「快速複習一本書」，有人要的是「把想法拆碎重新連結成自己的思想網」。結構必須長得不一樣。先別急著建資料夾，先回答問題。

---

## 0. 一個核心觀念：先決定光譜位置

所有讀書知識庫，本質上都在這條光譜上選一個位置：

```
以書為中心 ←─────────────────────────────→ 以想法為中心
（書摘型）                                  （卡片盒型 / Zettelkasten）

一本書 = 一頁                              一個想法 = 一張卡片
重點：保存、複習                           重點：連結、產出新想法
結構簡單，好維護                           結構複雜，威力大但要花心力
適合：工具書、教科書、備查                 適合：寫作、研究、深度思考
```

**這份 SOP 的所有問題，都是為了幫你找出「我該站在光譜的哪裡」。**
大多數人最後落在中間某處，而不是極端。

---

## 1. 怎麼使用這份 SOP

1. 開一個對話，對 Claude 說：**「帶我跑 SETUP-SOP」**
2. Claude 會照第 2~4 節，一批一批問你問題（不要一次丟 20 題）
3. 全部問完，Claude 對照第 5 節，提出 1~2 個結構建議給你選
4. 你確認後，Claude 照第 6 節實際建立資料夾、模板，並更新 `CLAUDE.md`

> 你不需要一次答完。可以分幾次，Claude 會記在 `wiki/meta/setup-訪談紀錄.md`。

---

## 2. 階段 A — 目的與痛點（最重要）

> 這批問題決定整個系統的方向。其他都是細節。

**A1. 你現在「讀完書之後」會發生什麼事？最讓你困擾的是哪個？**
- (a) 讀完就忘，過幾個月只記得「好像不錯」
- (b) 記得讀過，但要用的時候找不到是哪本書、哪一段
- (c) 每本書各自獨立，沒辦法把不同書的觀點串起來
- (d) 想把讀到的東西變成自己的輸出（寫作、簡報、決策）但卡住

**A2. 你希望這個知識庫一年後變成什麼？**（選最貼近的一句）
- (a) 一個「我讀過什麼」的可靠索引，要查隨時查得到
- (b) 一個「概念字典」，某個主題我能立刻調出所有相關書的說法
- (c) 一個「思想工作台」，幫我產生新想法、支援我寫作
- (d) 一個「考試/學習」用的複習系統，要能主動記住

**A3. 這是給「未來的你查」，還是會拿去「對外產出」（寫文章、教學、報告）？**

> **A1~A3 的解讀：**
> - 偏 (a)(b) → 光譜靠「書摘型」
> - 偏 (c)(d) → 光譜靠「想法中心 / 卡片盒型」
> - A3 若要對外產出 → 需要更嚴謹的原文出處與引用機制

---

## 3. 階段 B — 輸入（書與筆記從哪來）

**B1. 你讀的書主要是哪類？**（可複選，但標出主力）
- 技術 / 專業（程式、工程、財經實務）
- 學術（論文、教科書、需要嚴謹引用）
- 商業 / 自我成長
- 通識 / 人文（哲學、歷史、心理）
- 文學 / 小說

**B2. 你的筆記目前怎麼產生？**
- (a) 電子書畫線匯出（Kindle / Readwise / 中文電子書 App）
- (b) 邊讀邊自己打字寫筆記
- (c) 紙本書，拍照或事後憑印象整理
- (d) 還沒有任何筆記，想從零開始

**B3. 你想保存「原文」還是「你自己的話」？**
- (a) 原文金句一定要留（之後要引用、要精準）
- (b) 只留我自己消化後的重點就好
- (c) 兩者都要，但分開放

**B4. 一本書你大概會留多少？**
- 幾句金句 / 半頁重點 / 一頁完整摘要 / 拆成很多張小卡片

> **B1~B4 的解讀：**
> - B1 學術 + B3(a) → 出處頁碼機制要嚴格（沿用 CLAUDE.md 的來源標示規則）
> - B2(a) 匯出檔 → ingest 流程要能吃 highlights 格式
> - B3(c) / B4 拆小卡片 → 往卡片盒型走

---

## 4. 階段 C — 產出與規模（你會怎麼用它）

**C1. 你最常會做哪種查詢？**（排出前兩名）
- (a)「X 這本書到底在講什麼」→ 複習
- (b)「關於『習慣養成』，我讀過的書怎麼說」→ 跨書主題
- (c)「這句話是哪本書第幾頁說的」→ 找原文出處
- (d)「幫我把這幾本書的觀點整合成一篇」→ 綜合產出

**C2. 你想不想要「書與書之間自動連結」？**
- 例如讀 B 書時，系統提醒你「這跟你之前讀的 A 書某概念有關」
- (a) 很想，這正是我要的 / (b) 有最好，沒有也行 / (c) 不需要，太複雜

**C3. 規模感：你一年大概認真讀幾本？已經累積多少本想匯入？**
- 影響結構複雜度：< 10 本可以很簡單；> 30 本需要主題索引頁（MOC）

**C4. 你會固定回去「複習」嗎？還是只在需要時查？**
- 固定複習 → 可能要加「待複習」狀態、甚至間隔重複
- 只在需要時查 → 純被動索引就夠

> **C1~C4 的解讀：**
> - C1 偏 (b)(d) + C2(a) → 一定要做概念頁與 wikilink，往卡片盒型
> - C1 偏 (a)(c) → 書摘型 + 良好出處就夠
> - C3 數量大 → 加 `wiki/索引/` 主題地圖頁

## 6. 三種落地藍圖

### 藍圖一：書摘型（簡單、好維護）

```
raw/
  highlights/{書名}.md        ← 你的原始畫線、筆記
wiki/
  books/{書名}.md             ← 每本書一頁：摘要 + 金句 + 我的評價
  index.md                    ← 全部書的清單（可依主題分組）
```

每本書頁模板：
```markdown
---
title: 書名
author: 作者
status: 讀完 / 在讀 / 待讀
rating: ★★★★☆
sources: [raw/highlights/書名.md]
---
## 一句話總結
## 核心重點（3~5 條）
## 金句（附頁碼）
## 我的想法 / 可以怎麼用
```

### 藍圖二：卡片盒型（威力大、要花心力）

```
raw/
  highlights/{書名}.md
wiki/
  sources/{書名}.md           ← 文獻筆記：這本書說了什麼（你的話 + 出處）
  notes/{想法標題}.md         ← 永久筆記：一張卡片一個想法，原子化、互相 [[連結]]
  moc/{主題}.md               ← 主題地圖：把相關卡片串起來
```

永久筆記（卡片）模板：
```markdown
---
type: note
sources: [sources/書名.md p.123]
---
（用一兩句話講清楚一個、且只有一個想法）

相關：[[另一個想法]]、[[反對的想法]]
```

> 規則：一張卡片只放一個想法；想法用你自己的話；一定連到至少一張其他卡片。

### 藍圖三：混合型（推薦的預設）

以藍圖一為骨架（每本書一頁），但當某個概念在多本書反覆出現時，**才**把它抽成一張 `wiki/concepts/{概念}.md`，反向連結回各書。
→ 不強迫一開始就拆卡片，等知識自然長出連結再抽。低維護、可成長。

## 7. 確認後 Claude 要做的事（逐檔說明）

選定藍圖後，Claude 會動到這幾類檔案。**核心觀念：`CLAUDE.md` 是真正的「設定檔」**，它用「專案覆寫規則」蓋過 skill 預設值——個人化集中在這一個檔，skill 本體保持乾淨，未來 skill 更新版本也不會蓋掉你的設定。

| 檔案 | 動作 | 具體改什麼 |
|------|------|-----------|
| **CLAUDE.md** | 大改寫（重點） | 填 vault 路徑；術語從 `products/concepts/synthesis` 改成讀書語境 `books/notes/concepts/moc`；改寫「資料夾→wiki 編譯規則」表（highlights → 書頁）；調 ingest 規則讓它吃得下畫線匯出格式 |
| **README.md** | 中改 | 資料夾結構圖、工作流程改成選定的藍圖 |
| **Templates/** | 新建 | 把選定的筆記模板寫成檔案（書頁 或 卡片），ingest 時直接套用 |
| **資料夾骨架** | 新建 | 照藍圖建空的 `raw/highlights/`、`wiki/books/`（或 `notes/`、`moc/`）等 |
| **wiki/ 種子檔** | 新建 | `index.md`、`hot.md`、`log.md` 起始空殼 + `wiki/meta/setup-訪談紀錄.md`（存答案，未來改結構有依據） |
| **skills/** | 幾乎不動 | wiki-ingest/query 等維持原樣，客製全靠 CLAUDE.md 覆寫 |

最後：用一本真實的書跑一次 `/wiki-ingest` 驗證流程，再微調。

### 動手前一定先問你的兩件事（不自作主張）
1. **要不要接 git？** 目前 LLM-Wiki 不是 git repo。要版本控制才 `git init`。
2. **要不要納入 Obsidian 工作流？** `.obsidian/` 還在，這資料夾本身已是個 Obsidian vault，但要不要接進你 hub 的流程由你決定。

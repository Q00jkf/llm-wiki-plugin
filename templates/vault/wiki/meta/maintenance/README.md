# 系統維護紀錄

守門腳本自己寫的，**不要手改**。

| 檔 | 記什麼 | 誰寫 |
|---|---|---|
| `ledger.tsv` | 每支守門的 verdict **何時變過** | `_guard_status.record()` 自動 append |
| `../_guard-status/{機器}.json` | 每支守門**上次何時跑成功** | 同上 |
| `../doctor-report-YYYY-MM-DD.md` | 完整健檢報告（人寫的，收尾時存） | `/wiki-doctor` |

## 為什麼分類帳只記變化點，不是每次執行

一個連續 60 天 CLEAN 的系統，每次都記會產生 60 行一樣的內容 —— 看的人要自己找哪裡變過，
那就是雜訊，而雜訊久了沒人看。只記變化點的話，**穩定的系統幾乎不長，而每一行都是「這天開始不一樣了」**。

「上次何時跑過」不在這裡，那是 `_guard-status/` 的職責。兩者不重疊：
**一個回答「它還活著嗎」，一個回答「結果在變好還是變壞」。**

## 怎麼被使用

`vault_state.py` 開場讀它，**只在變差時出聲**：

- `CLEAN` → 有問題 ＝ 🔴
- 數字變大（`PENDING 120` → `PENDING 245`）＝ 🟡，附上日期與幅度
- 數字變小或持平 ＝ 不印（變好不需要打擾人）

超過 60 天以前的變化不再提 —— 那已經是現況不是新聞。

## 這份為什麼存在

單看一個數字沒辦法判斷要不要動手。看到 `PENDING 245` 不知道該不該緊張，
看到它「30 天內從 120 漲上來」才會。體檢報告一張看不出什麼，兩年份放一起才看得出在爬。
